# 小中学生向けプログラミングコンテストシステム 要件定義書

---

## 1. システム概要・基本方針

### 1.1 システムの目的
本システムは、小中学生（および保護者・指導者）からの作品応募受付け、事務局スタッフおよび審査員によるオンライン選考・評価の効率化、ならびに応募者への成長フィードバック（応援コメント等）の提供を統合的に行うためのWebプラットフォームである。

### 1.2 システムの基本方針
- **小中学生に配慮したUI/UX**: 分かりやすい用語使い、明確な入力フォーマット、自動入力補助テンプレートを提供し、応募時のストレスを最小化する。
- **公正で円滑な2段階審査**: 事務局スタッフによる一次審査（スクリーニング・一次採点）と、審査員による二次審査（最終選考）のワークフローをサポートする。
- **マルチデバイス・多様なツール対応**: ScratchやMicro:bitなどの主要プログラミングツールをはじめ、多様なジャンルのWeb共有URLや説明動画に対応する。

---

## 2. ユーザーロールおよび権限定義

システム内で定義する主要なユーザーロールと、それぞれのアクセス権限・可能操作は下表の通り。

| ロール名 | 対象ユーザー | アクセス権限および実行可能な主要操作 |
| :--- | :--- | :--- |
| **応募者** | 小中学生（および代理応募を行う保護者・教員） | ・アカウント登録・Google OAuthログイン<br>・応募フォームからの作品登録・編集（締切まで）<br>・マイページでの応募ステータス確認<br>・選考結果および審査員からの「公開コメント」の閲覧 |
| **事務局スタッフ** | コンテスト運営事務局担当者 | ・全応募作品の一次審査（スクリーニングおよびルーブリック採点）<br>・一次選考通過作品（上位20名程度）のフラグ付け・指定<br>・全般的な応募データの閲覧・検閲 |
| **審査員** | 外部・内部のコンテスト審査員 | ・担当に割り当てられた二次選考作品（上位20作品等）の閲覧<br>・二次審査用ルーブリック採点の入力<br>・公開コメント（応援メッセージ）および非公開コメント（内部メモ）の入力 |
| **システム管理者** | システム運用責任者 | ・スタッフ／審査員のアカウント発行・管理<br>・審査割り当て（重複設定）の構成<br>・最終集計結果・ランキングの出力・レポート化<br>・応募者への公開コメントフィードバックの一括公開設定 |

## 3. 機能要件

### 3.1 応募者向け機能（フロントエンド）

#### 1. 認証機能
- **Google ID連携認証 (Google OAuth)**:
  - Googleアカウントを利用したワンタップログイン／新規登録をサポートする。
- **メールアドレス会員登録**:
  - メールアドレスとパスワードによるアカウント作成。
  - メールアドレスの実在確認を行う二段階認証（メール認証リンク送付）を必須とする。

#### 2. 作品応募フォーム機能
応募者が作品を投稿するためのフォーム機能。入力項目および制約要件は以下の通り。

| 大分類 | 項目名 | 入力形式 | 必須/任意 | 制約・補足仕様 |
| :--- | :--- | :--- | :--- | :--- |
| **応募者情報** | 氏名 | 1行テキスト | **必須** | 全角文字（苗字・名前） |
| | フリガナ | 1行テキスト | **必須** | 全角カタカナ |
| | 学校名・学年 | ドロップダウン選択 | **必須** | 小学1年〜中学3年 |
| | 保護者氏名 | 1行テキスト | **必須** | 未成年応募に伴う確認事項 |
| | 保護者連絡先TEL | 1行テキスト | **必須** | ハイフンあり/なし両対応 |
| | 応募形態 | ラジオボタン | **必須** | 「個人」または「チーム」 |
| | チーム名・メンバー名 | 複数行テキスト | 任意 | 応募形態が「チーム」の場合のみ入力 |
| **作品提出** | 作品タイトル | 1行テキスト | **必須** | 最大 30文字 |
| | **作品URL** | URLテキスト | **必須** | Scratch共有URL、MakeCode共有URL、GitHub Pages等の公開URL |
| | **説明動画** | ラジオボタン ＋ 入力 | **必須** | 「YouTube URLの入力」または「MP4ファイル直接アップロード（最大100MB）」のいずれかを選択 |
| | **サムネイル画像** | ファイルアップロード | **必須** | PNG / JPG（最大 5MB、推奨アスペクト比 16:9） |
| **作品説明** | **短い説明** | 1行テキスト | **必須** | 最大 100文字（作品一覧画面等でのカード表示用サマリー） |
| | **作品の詳細説明** | Markdownテキストエリア | **必須** | 最大 2,000文字。下記テンプレートが自動挿入される |
| **確認・同意** | 応募規約・個人情報同意 | チェックボックス | **必須** | 保護者同意を含む規約同意チェック |

- **「作品の詳細説明」用初期導入テンプレート**:
  新規応募画面を開いた際、Markdownテキストエリアには以下のフォーマットがあらかじめ挿入される。
  ```markdown
  ## つくりかた
  （ここに作品のあそびかたや、つかいかたを書いてね）

  ## くふうしたところ
  （がんばったところや、じぶんだけのアイデアを書いてね）

  ## てつだってもらった ところ
  （おうちの人や先生に手伝ってもらったことがあれば書いてね。なければ「なし」でOK！）

```

#### 3. マイページおよび作品修正機能

* **マイページ**: ログイン後、自身が応募した作品の一覧および現在の選考ステータス（例:「受付済み」「一次審査中」「審査完了」）を閲覧可能。
* **差し替え・編集機能**: 応募締め切り日時までに限り、提出済みのすべての情報（タイトル、作品URL、動画、サムネイル、説明文章）の編集・更新を許可する。

### 3.2 審査・管理向け機能（バックエンド）

```
 [ 全応募作品 ]
        │
        ▼
 【 一次審査 】 (事務局スタッフ：1作品につき 4〜5名で重複採点)
   ・ルーブリック4軸（各1〜5点、計20点満点）
   ・平均スコアを自動算出 ➔ 上位20名程度を「二次審査対象」として抽出
        │
        ▼
 【 二次審査・最終選考 】 (審査員：1作品につき 4〜5名で重複採点)
   ・ルーブリック4軸（各1〜5点、計20点満点）
   ・「公開コメント（応援メッセージ）」および「非公開コメント（評価メモ）」を入力
        │
        ▼
 【 結果確定・フィードバック開示 】
   ・最終ランキング自動生成
   ・公開コメントの内容確認後、応募者マイページへフィードバック開示

```

#### 1. 一次審査機能（事務局スタッフ向け）

* **一覧・スクリーニングUI**:
* 全応募作品をリスト表示。不適切コンテンツや動作不全・リンク切れ作品の検閲・フラグ付けが可能。


* **一次採点画面**:
* 応募者の提出情報（動画プレビュー、作品URLリンク、整形されたMarkdownテキスト）を1画面で確認可能。
* 1作品に対し 4〜5名 のスタッフが割り当てられ、独立してルーブリック評価（5段階×4項目）を実施。


* **上位抽出機能**:
* 一次採点結果の平均点を算出し、スコア順で自動ソート。
* 上位20名程度の作品を一括指定し、「二次審査へ進出」ステータスへ更新する。



#### 2. 二次審査機能（審査員向け）

* **二次審査ダッシュボード**:
* 一次審査を通過した上位20作品の中から、自身に割り当てられた担当作品一覧を表示（未審査／一時保存／完了のステータス管理）。


* **詳細審査・採点画面**:
* **作品情報閲覧ゾーン**: MP4動画/YouTubeの埋め込み再生、Scratch等外部サイトへのリンク、整形されたMarkdownテキスト（つくりかた／くふうしたところ／てつだってもらったところ）を見やすく表示。
* **ルーブリック採点ゾーン**: 後述の4項目（1〜5点）をラジオボタン選択形式で入力。
* **コメント入力ゾーン**:
* **公開コメント（必須）**: 応募者の作品に対する良かった点、感動したポイント、今後のアドバイスなどの「応援コメント」。
* **非公開コメント（任意）**: 審査員間および事務局内部のみで共有される選考用の技術メモ・評価理由。


* **機能**: 一時保存機能、および最終確定送信機能。



#### 3. 管理者機能（集計およびフィードバック管理）

* **自動集計エンジン**:
* 各作品に対して複数名（4〜5名）の評価点を集計し、平均値・標準化スコア・合計値を算出。同点時の順位調整機能を保持。


* **コメント検閲および一括開示設定**:
* 審査員が入力した「公開コメント」一覧を管理者が事前確認（不適切な記述がないかの検閲）。
* コンテスト結果発表後、ワンクリックで応募者マイページへコメントを開示する。

## 4. 採点基準（ルーブリック評価仕様）

一次審査（事務局スタッフ）および二次審査（審査員）における評価は、以下の4軸×5段階評価（1項目につき1〜5点、満点20点）に基づく。

| 評価項目 | 定義・評価観点 | 評価スコア（1〜5点） |
| --- | --- | --- |
| **1. 独創性** | 作品に、他の人とは違うオリジナリティやアイデアが加えられているか | 1: 低い ～ 3: 標準 ～ 5: 極めて高い |
| **2. 技能** | 学年や年齢にふさわしい、プログラミングの知識・応用力・表現力が発揮されているか | 1: 低い ～ 3: 標準 ～ 5: 極めて高い |
| **3. 努力** | 作品、応募フォーム、写真、動画などが、手間や時間をかけて丁寧に作られているか | 1: 低い ～ 3: 標準 ～ 5: 極めて高い |
| **4. 目標** | 何かを便利にしたり、良くしたり、他の人を思いやったりする姿勢や目的意識があるか | 1: 低い ～ 3: 標準 ～ 5: 極めて高い |

## 5. データベース構造案（主要エンティティ）

```
[ Users ] ──1:N──> [ Submissions ] ──1:N──> [ Evaluations ]
                      │
                      └──1:N──> [ Comments ]

```

### 5.1 主要テーブル定義

1. **Users（ユーザーテーブル）**
* `user_id` (PK): ユーザー識別ID
* `auth_provider`: 認証プロバイダ (google / email)
* `email`: メールアドレス
* `name`: 氏名
* `name_kana`: フリガナ
* `school_name`: 学校名
* `grade`: 学年 (p1〜p6, m1〜m3)
* `guardian_name`: 保護者氏名
* `guardian_phone`: 保護者電話番号
* `role`: アカウント権限 (applicant / staff / judge / admin)


2. **Submissions（応募作品テーブル）**
* `submission_id` (PK): 作品識別ID
* `user_id` (FK): 応募者ID
* `entry_type`: 応募形態 (individual / team)
* `team_name`: チーム名
* `team_members`: メンバー氏名
* `title`: 作品タイトル
* `short_description`: 短い説明 (100文字以内)
* `detailed_description`: 詳細説明 (Markdown形式)
* `work_url`: 作品共有URL
* `video_type`: 動画種別 (youtube_url / mp4_file)
* `video_location`: 動画URLまたはストレージパス
* `thumbnail_url`: サムネイル画像パス
* `status`: 選考ステータス (submitted / primary_passed / final_completed)
* `created_at`: 応募日時
* `updated_at`: 最終修正日時


3. **Evaluations（評価・採点テーブル）**
* `evaluation_id` (PK): 採点識別ID
* `submission_id` (FK): 対象作品ID
* `evaluator_id` (FK): 採点者ID (Users.user_id)
* `phase`: 審査区分 (primary / secondary)
* `score_originality`: 独創性スコア (1〜5)
* `score_skill`: 技能スコア (1〜5)
* `score_effort`: 努力スコア (1〜5)
* `score_purpose`: 目標スコア (1〜5)
* `total_score`: 合計点 (算術計算値)
* `is_submitted`: 確定フラグ (Boolean)


4. **Comments（コメントテーブル）**
* `comment_id` (PK): コメント識別ID
* `submission_id` (FK): 対象作品ID
* `judge_id` (FK): 審査員ID
* `public_comment`: 応募者向け公開コメント（応援メッセージ）
* `private_comment`: 運営内部用非公開コメント
* `is_published`: フィードバック公開フラグ (Boolean)


追加・変更点：

ルーブリック4軸（各1〜5点、計20点満点）に「その他」を加えて、25点満点としてください。
その他だけは、同点を回避するため、小数点以下も入力可能とします。

応募フォームに、保護者のメールアドレスを入力する欄をもうけてください。
子供が応募すると保護者にメールが送られ、保護者はメールのリンクから「保護者の個人情報同意画面」に誘導され、コンテストの応募と個人情報の利用に同意させます。これが行われるまで、応募完了とはならないようにします。

審査員は、一覧で、自分の採点ステータスによるソートや、採点結果でソートできるようにしてください。
また、スタッフ審査の順位や審査員審査の総合点による順位もリアルタイムで確認できるようにします。
採点後に、元のデータが修正された場合は、審査済みのステータスが「要再審査」に変わるようにしてください。
