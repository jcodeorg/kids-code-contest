## Step 1: Supabaseプロジェクト作成 & DB構築

1. [Supabase](https://www.google.com/search?q=https://supabase.com/) にサインインし、新規プロジェクトを作成します（例: `kids-code-contest`）。
2. プロジェクト画面左メニューの **SQL Editor** を開きます。
3. 前回作成した **SQL DDL（最新版の全テーブル定義）** を貼り付けて `Run` ボタンを実行し、テーブル・ENUM・インデックスを一括作成します。

---

## Step 2: Supabase Auth（認証設定）

1. **Google OAuthの設定**:
* Google Cloud Console で OAuth 2.0 クライアントID を作成し、承認済みのリダイレクトURIに Supabase の `https://<YOUR-PROJECT-REF>.supabase.co/auth/v1/callback` を登録します。
* Supabaseの `Authentication` > `Providers` > `Google` にクライアントIDとシークレットを設定して有効化します。


2. **アカウント統合（Same Email Linking）の確認**:
* `Authentication` > `Providers` で **「Allow unverified email sign-ins」をオフ**にし、同アドレスの統合を確実に行う設定にします。



---

## Step 3: Next.js (App Router) ローカル開発環境作成

ターミナルで以下のコマンドを実行し、プロジェクトを作成します。

```bash
# Next.jsプロジェクト作成
npx create-next-app@latest kids-code-contest --typescript --tailwind --eslint --app

cd kids-code-contest

# Supabase公式SSRライブラリ等のインストール
npm install @supabase/supabase-js @supabase/ssr resend lucide-react

```

### 環境変数ファイル (`.env.local`) の作成

Supabaseの `Project Settings` > `API` から鍵を取得して設定します。

```env
NEXT_PUBLIC_SUPABASE_URL=https://<YOUR-PROJECT-REF>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key # API・管理者操作用
RESEND_API_KEY=re_123456789 # メール送信用（Resendなど）
NEXT_PUBLIC_APP_URL=http://localhost:3000

```

## Step 4: ユーザー登録 & 保護者同意メール送信の実装

1. **Supabase Client の作成 (`lib/supabase/client.ts` / `server.ts`)**:
* `@supabase/ssr` を使い、Client Component用およびServer Action/API Routes用のクライアントを初期化します。


2. **登録処理 (Server Action)**:
* ユーザーがフォーム送信時、`users` テーブルへ初期データ（`guardian_consent = 'pending'`、ランダム生成した `guardian_consent_token`）を挿入します。
* レスポンス返却と同時に、[Resend](https://www.google.com/search?q=https://resend.com) 等のメールAPIを呼び出し、保護者宛に承認用URL（例: `${NEXT_PUBLIC_APP_URL}/consent?token=${token}`）を送信します。



---

## Step 5: 保護者専用同意ページの実装

1. **同意画面ルート作成 (`app/consent/page.tsx`)**:
* URLパラメータから `token` を受け取ります。
* Supabaseの `Service Role Key`（特権クライアント）を使い、該当するトークンの `users` レコードを検索します。


2. **同意アクション (API / Server Action)**:
* 保護者が「同意する」ボタンを押下した際、`users` テーブルの `guardian_consent` を `'approved'` に更新し、`guardian_consent_at` に現在日時をセットします。



---

## Step 6: 招待リンク発行 & 権限自動付与ロジックの実装

1. **招待リンク発行 API (`app/api/admin/invite/route.ts`)**:
* 管理者が指定した `target_role`（`staff_primary` / `staff_manager` / `judge`）、`max_uses`（利用上限）、`expires_at`（有効期限）を元に、ランダムな `token` を生成して `invites` テーブルに保存します。


2. **招待経由の登録ルート (`app/invite/page.tsx`)**:
* ユーザーが `/invite?token=xxx` でアクセスした際、トークンの有効性を判定します（`status == 'active'` かつ `use_count < max_uses` かつ `expires_at > NOW()`）。
* 有効であればログイン/新規登録を案内し、認証完了時に Supabase Trigger または Server Action でユーザーの `role` を `target_role` へ変更し、`invite_usages` にログを記録します。



---

## Step 7: 管理者用ユーザー管理画面の構築

1. **アクセス制御（ミドルウェア `middleware.ts`）**:
* ログインユーザーの `role` を確認し、`role !== 'admin'` の場合は `/admin` 配下へのアクセスをリダイレクト（遮断）します。


2. **画面実装 (`app/admin/users/page.tsx`)**:
* `users` テーブルの一覧表示、検索窓、ロール・保護者同意ステータスのフィルタリングUIを実装します。
* ロールやステータスを直接変更できるモーダル/ドロップダウンを設置します。



---

## Step 8: GitHub連携 & Vercelへの本番デプロイ

1. **GitHubにコードをプッシュ**:
```bash
git add .
git commit -m "feat: complete auth and user management"
git push origin main

```


2. **Vercelヘデプロイ**:
* [Vercel](https://www.google.com/search?q=https://vercel.com/) にサインインし、**「Add New...」>「Project」** からGitHubリポジトリを選択します。
* **Environment Variables**（環境変数）の欄に、`.env.local` で設定した値（`NEXT_PUBLIC_APP_URL` は本番ドメインに変更）を入力します。
* **Deploy** を押せば、数分で本番環境が立ち上がります。
