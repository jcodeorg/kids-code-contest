# 認証・ユーザー登録・管理機能 システム仕様書

---

## 1. 概要・設計方針

### 1.1 目的

本仕様書は、小中学生向けプログラミングコンテストシステムにおける「ユーザー認証」「アカウント登録・保護者同意」「招待リンクによる権限自動付与」「管理者用ユーザー管理」に関する要件およびデータベース設計を統合的に定義するものである。

### 1.2 基本方針

* **即時応募可能な体験（楽観的アクセス制御）**: ユーザー登録直後から作品の入力・応募・修正（作品番号の発行含む）までを即座に許可し、小中学生の応募体験を阻害しない。ただし、事務局・審査員による審査対象（選考プール）に含めるには**保護者の同意が必須**となる。
* **役割に応じた権限の完全分離**: `admin`（システム管理者）はユーザー管理およびシステム保守のみを担当し、選考・集計操作には関与しない。業務運用は `staff_primary`（一次採点）、`staff_manager`（集計管理）、`judge`（審査員）に分離する。
* **アカウント統合（Same Email Linking）**: 同一のメールアドレスであれば、Google OAuth（SSO）およびメールアドレス＋パスワードのどちらからサインインしても同一人物のアカウント（同一レコード）として統合・処理する。
* **フレキシブルな招待機能**: 管理者は招待先（各ロール）に応じたワンタイム/マルチユースのトークン付き招待URLを発行でき、利用上限回数（1回のみ／指定回数／無制限）および有効期限を設定できる。

## 2. ユーザーロールおよび権限定義

システム内で定義する主要なユーザーロールとアクセス権限は下表の通り。

| ロール名 | ロールID (`user_role`) | 対象ユーザー | システム内のアクセス権限 |
| --- | --- | --- | --- |
| **応募者** | `applicant` | 児童・生徒・保護者 | 新規登録時の初期ロール。作品の応募・修正、マイページの閲覧 |
| **一次採点スタッフ** | `staff_primary` | 事務局スタッフ | 保護者同意完了済み作品の一次審査（動作確認・スクリーニング・一次採点）のみ |
| **集計管理スタッフ** | `staff_manager` | 運営事務局コアメンバー | 一次審査（必要に応じて採点可）、**審査進捗モニタリング、リアルタイム集計、上位選抜（20枠決定）、ランキング出力、不備データの修正・データメンテ** |
| **審査員** | `judge` | 審査員 | 二次審査（上位作品の詳細採点・ルーブリック評価・各種コメントの入力） |
| **システム管理者** | `admin` | システム運用担当 | **ユーザー管理（一覧・権限変更・アカウント有効化/無効化）、各種招待リンクの発行・管理のみ**（※選考や集計操作は不可） |

## 3. 機能要件

### 3.1 認証・アカウント登録・保護者同意フロー

#### 1. ユーザー登録・マルチ認証

* **Google ID連携認証 (Google OAuth)** および **メールアドレス＋パスワード** で登録・ログイン可能。
* 事前にメールアドレス検証（二段階認証リンクのクリック）を必須化し、同一メールアドレスであれば認証プロバイダを統合して同一アカウントとして処理する。

#### 2. 即時アクセス ＆ 保護者同意並行処理

1. **アカウント登録完了時**:
* ユーザー登録完了と同時にログイン状態となり、マイページアクセスおよび作品応募フォームの入力・送信（作品番号 `#100`〜 の自動発行）が可能。
* 登録と同時に、指定された `guardian_email` 宛へ「保護者同意リクエストメール（ワンタイム承認URL付き）」を自動送信する。


2. **マイページでのリマインド表示**:
* 保護者同意が未完了（`pending`）の間、応募者マイページ上に「⚠️ 保護者様の同意が完了していません。同意が完了するまで審査の対象になりません」という案内バナーと「同意メール再送」ボタンを常時表示する。


3. **保護者専用同意画面**:
* 保護者がメール内のリンクを開き、「コンテスト応募および個人情報の取り扱いに同意する」ボタンを押下することで、ステータスが `approved`（同意完了）へ更新される。


4. **審査対象（選考プール）への自動連動**:
* 一次採点スタッフおよび集計管理スタッフの画面には、**保護者同意ステータスが `approved` になったアカウントの作品のみが審査対象として表示される**。同意未完了の作品は「同意待ち」として別枠管理され、スタッフが無駄な採点を行わないよう保護される。



```text
 [アカウント登録] ➔ 即時ログイン可能！作品応募・修正・作品番号発行まで即時完了
        │
        ├── (A) 保護者同意「完了 (approved)」   ➔ 一次審査対象（選考プール）へ投入
        │
        └── (B) 保護者同意「未完了 (pending)」 ➔ 審査対象から一時除外（マイページにバナー表示 & 再送可）

```

---

### 3.2 招待・ロール付与機能（管理者 ➔ 運営・審査員）

1. **招待リンク発行機能（管理者用）**:
* 管理者が付与したい権限（`staff_primary` / `staff_manager` / `judge`）を選択してリンクを発行。
* **利用回数上限設定**: 「1回のみ（単発）」「指定回数（例: 10回）」「無制限」から選択可能。
* **有効期限設定**: デフォルト24時間（任意変更可）。


2. **招待リンク経由の登録フロー**:
* 対象者が招待URL（例: `[https://example.com/invite?token=xxx](https://example.com/invite?token=xxx)`）へアクセス。
* 有効性チェック（有効期限内かつ `use_count < max_uses`）を通過した場合、ログイン/登録完了時に指定されたロールを自動付与。
* 利用回数 `use_count` を +1 インクリメントし、利用履歴（`invite_usages`）を記録。



---

### 3.3 管理者（Admin）向けユーザー管理機能

1. **ユーザー一覧・検索・フィルタ**:
* 登録ユーザー全件のリスト表示。氏名・メールアドレス・学校名によるキーワード検索。
* ロール別（5つのロール）および保護者同意ステータス別（`pending` / `approved` / `rejected`）のフィルタリング。


2. **ロール直接変更・アカウント制御**:
* 登録済みユーザーのロール手動変更、および保護者同意ステータス・アカウント有効性の手動変更機能。


3. **招待管理・モニタリング**:
* 発行済み招待リンクの一覧表示（残り利用可能回数、有効期限、ステータス表示）、リンクの手動無効化（キャンセル）および再発行機能。

## 4. データベース設計（SQL DDL）

`guardian_consent`（保護者同意ステータス）を組み込んだ最新のデータベーススクリプトです。

```sql
-- 1. ユーザーロール定義 (ENUM)
CREATE TYPE user_role AS ENUM (
    'applicant',      -- 応募者
    'staff_primary',  -- 一次採点スタッフ
    'staff_manager',  -- 集計管理スタッフ
    'judge',          -- 審査員
    'admin'           -- システム管理者
);

-- 2. 保護者同意ステータス定義 (ENUM)
CREATE TYPE guardian_consent_status AS ENUM (
    'pending',   -- 保護者同意待ち（作品応募・修正は可能だが審査対象外）
    'approved',  -- 保護者同意完了（正式に審査対象）
    'rejected'   -- 保護者により拒否
);

-- 3. 招待ステータス定義 (ENUM)
CREATE TYPE invite_status AS ENUM ('active', 'exhausted', 'expired', 'cancelled');

-- 4. ユーザーテーブル (users)
CREATE TABLE users (
    user_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) NOT NULL UNIQUE,          -- アカウント統合のキーとなる一意アドレス
    auth_provider VARCHAR(50) NOT NULL DEFAULT 'email', -- 'google', 'email', 'multiple'
    name VARCHAR(100) NOT NULL,
    name_kana VARCHAR(100),
    school_name VARCHAR(100),
    grade VARCHAR(20),
    guardian_name VARCHAR(100),
    guardian_email VARCHAR(255),
    guardian_phone VARCHAR(50),
    guardian_consent guardian_consent_status NOT NULL DEFAULT 'pending', -- 保護者同意ステータス
    guardian_consent_at TIMESTAMP WITH TIME ZONE,                        -- 同意完了日時
    guardian_consent_token VARCHAR(255) UNIQUE,                          -- 保護者承認用トークン
    role user_role NOT NULL DEFAULT 'applicant',                         -- 単一ロール管理
    is_active BOOLEAN NOT NULL DEFAULT true,                             -- アカウント有効化フラグ
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 5. 招待管理テーブル (invites)
CREATE TABLE invites (
    invite_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    token VARCHAR(255) NOT NULL UNIQUE,           -- ワンタイム/マルチユース トークン
    target_role user_role NOT NULL,             -- 付与する権限 ('staff_primary', 'staff_manager', 'judge')
    max_uses INT NOT NULL DEFAULT 1,            -- 利用上限回数 (1: 単発, N: 複数回利用可能)
    use_count INT NOT NULL DEFAULT 0,           -- 現在の利用達成回数
    status invite_status NOT NULL DEFAULT 'active',
    expires_at TIMESTAMP WITH TIME ZONE NOT NULL, -- 有効期限
    created_by_user_id UUID NOT NULL REFERENCES users(user_id), -- 発行した管理者ID
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 6. 招待利用履歴テーブル (invite_usages)
CREATE TABLE invite_usages (
    usage_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    invite_id UUID NOT NULL REFERENCES invites(invite_id) ON DELETE CASCADE,
    used_by_user_id UUID NOT NULL REFERENCES users(user_id), -- 登録・権限昇格したユーザーID
    used_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 検索・パフォーマンス向上のためのインデックス設定
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_role ON users(role);
CREATE INDEX idx_users_guardian_consent ON users(guardian_consent);
CREATE INDEX idx_invites_token ON invites(token);
CREATE INDEX idx_invites_status ON invites(status);
CREATE INDEX idx_invite_usages_invite ON invite_usages(invite_id);

```
