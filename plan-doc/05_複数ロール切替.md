# 複数ロール割り当て＆動的ロール切替（スイッチ）機能 仕様書

---

## 1. 機能概要

本機能は、1つのユーザーアカウントに対して複数の操作権限（ロール）を付与し、ユーザーがログイン中や操作中に自らアクティブなロールを動的に切り替えられるようにするアクセス制御メカニズムである。

アカウントの付け替え（ログアウト・ログイン）を行うことなく、同一アカウントのまま「応募者」としての作品管理と「一次採点スタッフ」や「審査員」としての選考業務をスムーズに兼任・切り替えて操作できる。

---

## 2. ロール定義一覧

システムで定義するロール、日本語表示名、およびそれぞれの役割・実行可能操作は以下の通り。

| ロールID (`role_id`) | 日本語表示名 | 役割・対象ユーザー | 実行可能な主要操作・アクセス範囲 |
| --- | --- | --- | --- |
| **`applicant`** | **応募者** | 小中学生・代理応募者 | ・作品ライブラリの管理、コンテストへのエントリー<br>

<br>・応募ステータス・作品番号（例: #101）の確認<br>

<br>・選考結果および公開コメントの閲覧 |
| **`staff`** | **一次採点スタッフ** | 一次選考担当スタッフ | ・割り当てられた応募作品の一次審査（ルーブリック採点）入力<br>

<br>・作品番号、カテゴリー、工作物有無による検索・フィルタリング |
| **`contest_admin`** | **コンテスト管理者** | 事務局選考責任者・運営リーダー | ・一次審査の進捗・平均点スコア一覧のリアルタイム確認<br>

<br>・一次審査通過作品（上位20件等）の一括フラグ（`is_primary_passed`）設定<br>

<br>・一次審査順位および審査員総合順位のリアルタイム確認 |
| **`admin`** | **システム管理者** | システム運用・保守責任者 | ・新規コンテスト（年度・開催情報）の作成・設定<br>

<br>・各ユーザーへのロール（マルチロール）割り当て・変更<br>

<br>・システムログ監査およびバックアップ管理 |

## 3. ロール切替（スイッチング）動作およびセキュリティ仕様

### 3.1 画面UIおよび操作フロー

* **切替UIの配置**:
* 画面上部グローバルナビゲーションバー（ヘッダーゾーン）のユーザーアイコン付近に「ロール切替ドロップダウン」を配置する。


* **切替時の挙動**:
* ユーザーがドロップダウンから保持している別ロールを選択すると、アクティブロールが変更される。
* 切替完了後、自動的に新しく選択されたロール専用の**ダッシュボード画面**へ遷移する。



### 3.2 次回ログイン時の自動選択とセキュリティ対策（ロール剥奪時の不正防止）

管理者が事前に該当ユーザーのロール割当（`User_Roles`）を削除・剥奪した場合、旧 `current_role_id` での不正アクセスを防止するため、ログイン時およびロール切替時に以下の多重セキュリティ検証を実施する。

```text
  [ ログイン処理開始 ]
           │
           ▼
  【 検証 1: current_role_id の有効性チェック 】
  Users.current_role_id が User_Roles テーブルに存在するか確認
           │
     ┌─────┴─────┐
    [存在]     [非存在（削除済）]
     │           │
     │           ▼
     │   【 フォールバック処理 (Fallback) 】
     │   User_Roles から該当ユーザーが保持する別の有効なロールを1つ自動取得
     │   （最優先: 'applicant' などの最下位権限、または割り当て済みロールの1番目）
     │           │
     │     ┌─────┴─────┐
     │    [有]        [無（全権限削除）]
     │     │           │
     │     ▼           ▼
     │  Users.current_role_id を ➔ 403 Access Denied
     │  有効ロールで上書き更新      （ログイン拒否・アカウント無効化）
     │     │
     └─────┬─────┘
           │
           ▼
  【 検証 2: APIリクエストごとの動的権限チェック 】
  すべてのAPIリクエスト実行時、セッションの current_role_id が
  User_Roles に依然として存在するかをリアルタイム検証する

```

1. **ログイン時検証と自動フォールバック（Fallback）**:
* ログイン時、`Users.current_role_id` に設定されているロールが、現在も `User_Roles` テーブルに存在するか検証する。
* **剥奪検知時**: 管理者によって `current_role_id` の権限が削除されていた場合、システムは自動的に現在割り当てられている別の有効なロール（例: 最基本ロール `applicant` 等）に `Users.current_role_id` を上書き変更し、そのロールのダッシュボードへ安全に誘導する。
* **全権限削除時**: `User_Roles` に有効なロールが1つも存在しない場合は、ログインを拒否し「利用可能な権限がありません。管理者にお問い合わせください」のエラー（403 Forbidden）を返す。


2. **APIリクエストごとの動的認可チェック（Token / Session Validation）**:
* 画面操作中（API実行時）も、リクエストヘッダーで送られた `current_role_id` が DB（`User_Roles`）上に現在も存在するかをチェックする。
* セッション途中で管理者に権限を削除された場合、即座に 403 エラーを返して再ログイン・画面リロードを促す。

## 4. データベース定義（SQL）

本機能を構築するための PostgreSQL 準拠の DDL（テーブル作成SQL）です。

```sql
-- ============================================================
-- 1. ロールマスターテーブル (Roles)
-- ============================================================
CREATE TABLE roles (
    role_id VARCHAR(30) PRIMARY KEY,
    role_name VARCHAR(50) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

COMMENT ON TABLE roles IS 'システムロールマスター';
COMMENT ON COLUMN roles.role_id IS 'ロール識別キー (applicant, staff, contest_admin, judge, admin)';
COMMENT ON COLUMN roles.role_name IS '日本語表示名';

-- 初期データ投入
INSERT INTO roles (role_id, role_name) VALUES
('applicant',     '応募者'),
('staff',         '一次採点スタッフ'),
('contest_admin', 'コンテスト管理者'),
('judge',         '審査員'),
('admin',         'システム管理者');

-- ============================================================
-- 2. ユーザーテーブル (Users) - 関連カラム抜粋
-- ============================================================
CREATE TABLE users (
    user_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL,
    -- 現在選択中（次回ログイン時デフォルト）のロールID
    current_role_id VARCHAR(30) NOT NULL DEFAULT 'applicant',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    
    -- 外部キー制約
    CONSTRAINT fk_users_current_role 
        FOREIGN KEY (current_role_id) 
        REFERENCES roles(role_id) 
        ON DELETE RESTRICT 
        ON UPDATE CASCADE
);

COMMENT ON COLUMN users.current_role_id IS '現在選択中（次回ログイン時デフォルト）のロールID';

-- ============================================================
-- 3. ユーザー・ロール関連付けテーブル (User_Roles)
-- ============================================================
CREATE TABLE user_roles (
    user_id UUID NOT NULL,
    role_id VARCHAR(30) NOT NULL,
    assigned_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    
    -- 複合主キー（同一ユーザーへの重複割り当てを防止）
    PRIMARY KEY (user_id, role_id),
    
    -- 外部キー制約（ユーザー削除時はカスケード削除、ロールマスタ削除は制限）
    CONSTRAINT fk_user_roles_user 
        FOREIGN KEY (user_id) 
        REFERENCES users(user_id) 
        ON DELETE CASCADE,
        
    CONSTRAINT fk_user_roles_role 
        FOREIGN KEY (role_id) 
        REFERENCES roles(role_id) 
        ON DELETE RESTRICT 
        ON UPDATE CASCADE
);

COMMENT ON TABLE user_roles IS 'ユーザーとロールの多対多割り当て中間テーブル';

-- インデックス作成（検索パフォーマンス最適化）
CREATE INDEX idx_user_roles_user_id ON user_roles(user_id);

```

## 5. バックエンド API 認可・セキュリティ制御ロジック（疑似コード）

```python
def handle_user_login(user_id):
    # 1. ユーザー基本情報の取得
    user = db.query("SELECT * FROM users WHERE user_id = :user_id", user_id=user_id)
    
    # 2. 現在割り当てられている有効なロール一覧を取得
    assigned_roles = db.query(
        "SELECT role_id FROM user_roles WHERE user_id = :user_id", 
        user_id=user_id
    )
    assigned_role_ids = [r.role_id for r in assigned_roles]
    
    # 【セキュリティチェック 1】割り当てロールが0件の場合
    if not assigned_role_ids:
        raise HTTPException(status_code=403, detail="利用可能な権限がありません。管理者にお問い合わせください。")
    
    # 【セキュリティチェック 2】current_role_id が剥奪・削除されていないか判定
    active_role = user.current_role_id
    if active_role not in assigned_role_ids:
        # フォールバック処理: 有効なロールの先頭（例: 'applicant' 等）を強制選択
        active_role = assigned_role_ids[0]
        # DB上の current_role_id を安全なロールで更新
        db.execute(
            "UPDATE users SET current_role_id = :role_id WHERE user_id = :user_id",
            role_id=active_role, user_id=user_id
        )
    
    # 3. 認証トークン(JWT等)の発行
    token = create_jwt_token(user_id=user.user_id, current_role=active_role)
    return {"token": token, "active_dashboard": f"/dashboard/{active_role}"}

```
