## 1. 推奨技術スタック案

小中学生向けのシンプルなUI、リアルタイムな集計機能、外部連携（Google OAuth, メール送信）を効率良く実現するための構成案です。

* **フロントエンド**: **Next.js (React) + Tailwind CSS**
* **理由**: 応募者用画面、保護者同意画面、審査員用ダッシュボードを単一リポジトリ（Webシステム）として効率よく開発可能。Markdownの入力・表示ライブラリが豊富。


* **バックエンド / DB**: **Supabase** (PostgreSQL + Auth + Storage)
* **認証**: Google OAuth および メール認証（保護者ワンタイムURL）を標準機能で安全に実装可能。
* **データベース**: PostgreSQLによるリアルタイム集計機能（ビューやトリガー）が強力。
* **ストレージ**: 動画（MP4）やサムネイル（PNG/JPG）のアップロード管理。


* **メール配信**: **Resend** または **SendGrid**
* **理由**: 保護者宛の同意リクエストメール（トランザクションメール）の到達率が高く、API経由で即座に送信可能。

## 2. 段階的実装ロードマップ（Phase 1 〜 4）

一気にすべてを作るのではなく、コア機能から順番に構築してテストを進めるアプローチが最も失敗が少ないです。

```
[ Phase 1: DB・認証基盤 ] ➔ [ Phase 2: 応募・保護者同意 ] ➔ [ Phase 3: 審査・集計 ] ➔ [ Phase 4: マイページ・仕上げ ]

```

### Phase 1: データベース構築・認証基盤

1. **DBスキーマ作成**: 要件定義書の主要5テーブル（`Users`, `Submissions`, `Parent_Consents`, `Evaluations`, `Comments`）を定義。
2. **自動採番ロジック**: `work_number` を `100` から自動インクリメント（Sequence機能等）する設定。
3. **認証実装**: Google ID連携およびメールアドレスログインの実装。

### Phase 2: 応募フォーム & 保護者同意フロー（応募者・保護者向け）

1. **応募フォームUI実装**:
* Markdown初期テンプレート自動セット機能
* MP4/YouTube切替機能、画像アップロード機能


2. **作品登録 ➔ 保護者メール送信**:
* 送信時に仮ステータス（`pending_consent`）で登録し、保護者へワンタイムURLをメール送付。


3. **保護者同意ページ**:
* トークン検証後、ステータスを正式応募（`submitted`）へ更新。



### Phase 3: 審査員ダッシュボード & リアルタイム集計（スタッフ・審査員向け）

1. **審査画面UI（プレビュー＆ルーブリック入力）**:
* 動画埋め込み、作品URLリンク、Markdown表示、5軸採点フォーム（「その他」の少数点入力対応）。


2. **ソート＆リアルタイム集計**:
* 作品番号順、ステータス順（未審査／要再審査など）、スコア順のソート。
* 一次審査順位・審査員総合順位のリアルタイム算出。


3. **修正検知＆「要再審査」連動**:
* 応募データ更新時に採点ステータスを `re_examine_required` へ自動更新するDBトリガーまたはAPIロジック。



### Phase 4: 応募者マイページ & フィードバック開示

1. **マイページUI**:
* 作品番号（例: `#105`）の強調表示、ステータス表示、提出締め切り前の編集機能。


2. **フィードバック開示機能**:
* コンテスト終了後、管理者の公開ボタン押下で「公開コメント」がマイページ上に表示される仕組み。
