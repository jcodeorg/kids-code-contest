ご提示いただいた「`Evaluations` と `Comments` のテーブル統合」を反映し、システム全体の設計とドキュメントを再構築いたしました。

データ構造がよりシンプルに整理され、審査員が入力する「点数」と「フィードバックコメント」が1つのトランザクションとして安全かつ効率的に扱える構成になっています。

# 小中学生向けプログラミングコンテストシステム 要件定義・データベース設計書（確定版）

---

## 1. システム概要・基本方針

### 1.1 システムの目的

本システムは、小中学生（および保護者・指導者）による作品ポートフォリオの蓄積とコンテストへのエントリー、保護者同意プロセスの自動化、事務局スタッフおよび審査員による多段階（一次・二次）オンライン選考・評価の効率化、ならびに応募者への成長フィードバック（公開コメント等）を提供する統合Webプラットフォームである。

### 1.2 システムの基本方針

* **ポートフォリオ型応募管理**: 応募者は自身の作品をマイページ（ライブラリ）に複数保存でき、その中から指定のコンテストへ1作品を選択してエントリーする。
* **小中学生に配慮したUI/UX**: 子ども自身が自身の応募作品を認識しやすいよう、コンテストごとに100から始まる「作品番号」を自動発行する。
* **厳格な保護者同意フロー**: 未成年者の応募および個人情報利用に対し、保護者宛のメール検証・承認ステップを必須化することで法的なコンプライアンスを担保する。
* **マルチ年度対応・柔軟な2段階審査**: プログラム改修なしで毎年新しいコンテストを開催できる構造とし、1つのコンテスト内で「一次審査（スタッフ）」および「二次審査（審査員）」を審査フェーズ（Phase）として分離・管理する。
* **評価・コメントの一体化データ構造**: 採点数値とフィードバックコメントを1つの評価データ（Evaluations）として統合管理し、システム処理の高速化とデータ整合性を維持する。

## 3. 機能要件

### 3.1 応募者・保護者向け機能（フロントエンド）

#### 1. 認証・作品ライブラリ管理機能

* **認証**: Google ID連携認証 (Google OAuth) およびメールアドレス＋パスワード会員登録（二段階認証付き）をサポート。
* **作品ライブラリ（マイポートフォリオ）**: ユーザーは締め切りに関わらず、自身の作品データ（タイトル、説明、URL、動画、サムネイル）をマイページ上に複数登録・保存・編集できる。

#### 2. コンテスト応募（エントリー）機能

* **エントリー制限**: 1つのコンテストに対し、ライブラリの中から選択できる作品は**1ユーザーにつき1作品**のみ。
* **自動発行作品番号**: エントリー完了時、対象コンテスト内で100から始まる3桁の整数「作品番号」を自動発行（例: #100, #101... 欠番可）。

#### 3. 保護者同意 ＆ 修正・再審査連動ワークフロー

1. **仮応募と同意送信**: 応募者がエントリーボタンを押下した時点で「保護者同意待ち」ステータスとなり、保護者宛に承認トークン付きURLを自動送信。
2. **同意完了**: 保護者が画面から同意を実行した時点で正式なエントリー（`submitted`）となり、審査対象となる。
3. **作品修正と「要再審査」連動**: 応募締め切り前であれば提出作品の更新が可能。審査完了済みの作品が更新された場合、該当フェーズ（一次または二次）の採点データステータスを自動的に「要再審査（`re_examine_required`）」へ変更する。

---

### 3.2 審査・管理向け機能（バックエンド）

```text
 [ 応募作品一覧 ] (コンテストにエントリー完了した全作品／作品番号 #100〜)
        │
        ▼
 【 一次審査 (phase = primary) 】 (事務局スタッフ)
   ・ルーブリック5軸採点（最大25.0点）
   ・平均スコア自動算出
        │
        ▼
 【 集計・二次審査進出決定 】 (システム管理者)
   ・一次審査平均点の上位20件を抽出し「一次通過フラグ (is_primary_passed)」をONに設定
        │
        ▼
 【 二次審査 (phase = final) 】 (審査員)
   ・一次通過作品のみを対象にルーブリック5軸採点 ＋ コメント（公開／非公開）入力
   ・一次審査順位 ＆ 審査員総合順位のリアルタイム表示
        │
        ▼
 【 結果確定・フィードバック開示 】 (システム管理者)
   ・最終ランキング自動生成
   ・採点データ内の「公開コメントフラグ (is_comment_published)」を一括送信してマイページに表示

```

#### 1. 一次審査機能（スタッフ用 / `phase: primary`）

* 保護者同意が完了した全エントリー作品をリスト表示（作品番号ソート・ダイレクト検索可能）。
* 1作品に対し複数名のスタッフが独立してルーブリック評価を実施し、採点データを `phase = 'primary'` として蓄積。

#### 2. 管理者ツール（一次通過処理）

* 一次審査（`phase = 'primary'`）の採点結果から自動で平均点を算出・ランキング表示。
* 上位20件を選択し、エントリーデータに対し `is_primary_passed = True` フラグを一括付与。

#### 3. 二次審査機能（審査員用 / `phase: final`）

* **対象絞り込み**: `is_primary_passed = True` の作品のみを表示。
* **リアルタイム順位表示**: 「一次審査順位（スタッフ採点結果）」と「審査員総合順位（二次審査リアルタイム集計）」を画面上に常時表示。
* **採点＋コメントの同時登録**: 審査員はルーブリック5軸の入力に加え、応募者向けの「公開コメント（必須）」と「非公開メモ（任意）」を同じ画面・1回の保存アクションで完了させる。

## 4. 採点基準（ルーブリック評価仕様）

一次審査（`phase: primary`）および二次審査（`phase: final`）共通で以下の5軸評価（最大25.0点）を用いる。

| 評価項目 | 定義・評価観点 | 入力形式 / 評価スコア | 補足仕様 |
| --- | --- | --- | --- |
| **1. 独創性** | 他の人とは違うオリジナリティやアイデアがあるか | 整数（1〜5点） | 1: 低い ～ 3: 標準 ～ 5: 極めて高い |
| **2. 技能** | 学年・年齢にふさわしいプログラミング技術・表現力か | 整数（1〜5点） | 1: 低い ～ 3: 標準 ～ 5: 極めて高い |
| **3. 努力** | 手間や時間をかけて丁寧に作られているか | 整数（1〜5点） | 1: 低い ～ 3: 標準 ～ 5: 極めて高い |
| **4. 目標** | 目的意識や誰かを思いやる姿勢があるか | 整数（1〜5点） | 1: 低い ～ 3: 標準 ～ 5: 極めて高い |
| **5. その他** | 総合的な魅力、将来性、感銘度 | 小数第1位まで（1.0〜5.0点） | 【同点回避用】例: 4.3点など細かな調整 |

## 5. データベース構造定義（ER構造・主要テーブル）

### 5.1 エンティティ関係図 (ER Diagram)

```text
[ Users ] ──1:N──> [ Works ] ──1:N──> [ Contest_Entries ] ◄──N:1── [ Contests ]
                       │                      │
                       │                      ├──1:N──> [ Evaluations (採点・コメント) ]
                       │                      │
                       │                      └──1:1──> [ Parent_Consents ]

```

---

### 5.2 主要テーブル定義

#### 1. Users（ユーザーテーブル）

システムを利用する全ユーザー（応募者、スタッフ、審査員、管理者）を管理する。

| カラム名 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| `user_id` | UUID / BIGINT | PK | ユーザー識別ID |
| `auth_provider` | VARCHAR(20) | NOT NULL | 認証種別 (`google` / `email`) |
| `email` | VARCHAR(255) | UNIQUE, NOT NULL | メールアドレス |
| `name` | VARCHAR(100) | NOT NULL | 氏名 |
| `name_kana` | VARCHAR(100) | NOT NULL | フリガナ |
| `school_name` | VARCHAR(100) | NOT NULL | 学校名 |
| `grade` | VARCHAR(10) | NOT NULL | 学年 (`p1`〜`p6`, `m1`〜`m3`) |
| `guardian_name` | VARCHAR(100) | NOT NULL | 保護者氏名 |
| `guardian_email` | VARCHAR(255) | NOT NULL | 保護者メールアドレス |
| `guardian_phone` | VARCHAR(20) | NOT NULL | 保護者電話番号 |
| `role` | VARCHAR(20) | NOT NULL | 権限 (`applicant`, `staff`, `judge`, `admin`) |

#### 2. Contests（コンテスト管理テーブル）

年度ごとのコンテスト開催情報を保持する。プログラム修正なしで次年度を追加可能。

| カラム名 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| `contest_id` | BIGINT | PK, AUTO_INC | コンテスト識別ID |
| `title` | VARCHAR(100) | NOT NULL | 大会名（例: 「2026年度プログラミングコンテスト」） |
| `year` | INT | NOT NULL | 開催年度（例: 2026） |
| `status` | VARCHAR(20) | NOT NULL | フェーズ (`draft`, `accepting`, `primary_judging`, `final_judging`, `completed`) |
| `entry_start_at` | DATETIME | NOT NULL | 応募開始日時 |
| `entry_end_at` | DATETIME | NOT NULL | 応募締め切り日時 |

#### 3. Works（作品ライブラリテーブル）

応募者がマイページに作成・ストックする作品本体データ（複数作成可）。

| カラム名 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| `work_id` | UUID / BIGINT | PK | 作品識別ID |
| `user_id` | UUID / BIGINT | FK(Users), NOT NULL | 所有者ユーザーID |
| `title` | VARCHAR(30) | NOT NULL | 作品タイトル |
| `short_description` | VARCHAR(100) | NOT NULL | 短い説明 |
| `detailed_description` | TEXT | NOT NULL | 詳細説明 (Markdown) |
| `work_url` | TEXT | NOT NULL | 作品共有URL |
| `video_type` | VARCHAR(20) | NOT NULL | 動画形式 (`youtube_url` / `mp4_file`) |
| `video_location` | TEXT | NOT NULL | 動画URLまたはストレージパス |
| `thumbnail_url` | TEXT | NOT NULL | サムネイル画像ストレージパス |
| `created_at` | DATETIME | NOT NULL | 作成日時 |
| `updated_at` | DATETIME | NOT NULL | 更新日時 |

#### 4. Contest_Entries（コンテストエントリーテーブル）

どの作品が、どのコンテストに応募されたかを管理する。

| カラム名 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| `entry_id` | BIGINT | PK, AUTO_INC | エントリー識別ID |
| `contest_id` | BIGINT | FK(Contests), NOT NULL | 応募先コンテストID |
| `work_id` | UUID / BIGINT | FK(Works), NOT NULL | 応募作品ID |
| `user_id` | UUID / BIGINT | FK(Users), NOT NULL | 応募者ID |
| `work_number` | INT | NOT NULL | **作品番号（コンテストごとに100から自動採番）** |
| `entry_type` | VARCHAR(10) | NOT NULL | 応募形態 (`individual` / `team`) |
| `team_name` | VARCHAR(100) | NULL | チーム名 |
| `team_members` | TEXT | NULL | メンバー氏名 |
| `status` | VARCHAR(30) | NOT NULL | 状態 (`pending_consent`, `submitted`, `final_completed`) |
| `is_primary_passed` | BOOLEAN | DEFAULT FALSE | **一次審査通過フラグ（上位20件抽出でTRUE化）** |
| `created_at` | DATETIME | NOT NULL | エントリー日時 |

> **一意性制約 (UNIQUE Constraint)**: `(contest_id, user_id)` の複合キーを設定し、1つのコンテストに対して1ユーザーが1作品しかエントリーできない制約を担保。

#### 5. Parent_Consents（保護者同意テーブル）

エントリーに対する保護者の同意手続き状況を管理する。

| カラム名 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| `consent_id` | BIGINT | PK, AUTO_INC | 同意管理ID |
| `entry_id` | BIGINT | FK(Contest_Entries), UNIQUE | 対象エントリーID |
| `token` | VARCHAR(64) | UNIQUE, NOT NULL | ワンタイム承認トークン |
| `status` | VARCHAR(20) | NOT NULL | 状態 (`pending`, `approved`, `expired`) |
| `approved_at` | DATETIME | NULL | 同意完了日時 |

#### 6. Evaluations（評価・採点・コメントテーブル）※統合版

採点数値データおよび審査コメントを統合して管理する。

| カラム名 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| `evaluation_id` | BIGINT | PK, AUTO_INC | 評価識別ID |
| `entry_id` | BIGINT | FK(Contest_Entries), NOT NULL | 対象エントリーID |
| `evaluator_id` | UUID / BIGINT | FK(Users), NOT NULL | 採点者ID (スタッフまたは審査員) |
| **`phase`** | **VARCHAR(20)** | **NOT NULL** | **審査区分 (`primary`: 一次審査 / `final`: 二次審査)** |
| `score_originality` | INT | NOT NULL | 独創性 (1〜5) |
| `score_skill` | INT | NOT NULL | 技能 (1〜5) |
| `score_effort` | INT | NOT NULL | 努力 (1〜5) |
| `score_purpose` | INT | NOT NULL | 目標 (1〜5) |
| `score_other` | DECIMAL(2,1) | NOT NULL | その他 (1.0〜5.0) |
| `total_score` | DECIMAL(3,1) | NOT NULL | 合計点 (最大25.0) |
| **`public_comment`** | **TEXT** | **NULL** | **応募者向け公開コメント（二次審査時必須）** |
| **`private_comment`** | **TEXT** | **NULL** | **運営内部用メモ（任意）** |
| **`is_comment_published`** | **BOOLEAN** | **DEFAULT FALSE** | **公開コメントのマイページ開示フラグ** |
| `status` | VARCHAR(30) | NOT NULL | 採点状態 (`draft`, `completed`, `re_examine_required`) |
| `updated_at` | DATETIME | NOT NULL | 採点・更新日時 |

> **一意性制約 (UNIQUE Constraint)**: `(entry_id, evaluator_id, phase)` の複合キーを設定し、1人の採点者が同一作品・同一フェーズにおいて重複して評価を作成することを防ぐ。
