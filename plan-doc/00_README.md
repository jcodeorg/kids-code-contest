# 小中学生向けプログラミングコンテストシステム 要件定義書
kids-code-contest
---

## 1. システム概要・基本方針

### 1.1 システムの目的

本システムは、小中学生（および保護者・指導者）からの作品応募受付け、保護者同意プロセスの自動化、事務局スタッフおよび審査員によるオンライン選考・評価の効率化、ならびに応募者への成長フィードバック（応援コメント等）の提供を統合的に行うためのWebプラットフォームである。

### 1.2 システムの基本方針

* **小中学生に配慮したUI/UX**: 分かりやすい用語使い、明確な入力フォーマット、自動入力補助テンプレートを提供し、応募時のストレスを最小化する。また、子ども自身が自分の作品を識別しやすいよう、100から始まる「作品番号」を発行する。
* **厳格な保護者同意フロー**: 未成年者の応募および個人情報利用に対し、保護者宛のメール検証・承認ステップを必須化することで法的なコンプライアンスを担保する。
* **公正でリアルタイムな2段階審査**: 事務局スタッフによる一次審査と審査員による二次審査のワークフローをサポートし、リアルタイム順位表示や修正検知による「要再審査」ステータス管理を行う。
* **マルチデバイス・多様なツール対応**: ScratchやMicro:bitなどの主要プログラミングツールをはじめ、多様なジャンルのWeb共有URLや説明動画に対応する。

## 2. ユーザーロールおよび権限定義

システム内で定義する主要なユーザーロールと、それぞれのアクセス権限・可能操作は下表の通り。

| ロール名 | 対象ユーザー | アクセス権限および実行可能な主要操作 |
| --- | --- | --- |
| **応募者** | 小中学生（および代理応募を行う保護者・教員） | ・アカウント登録・Google OAuthログイン<br>

<br>・応募フォームからの作品登録・編集（締切まで）<br>

<br>・マイページでの応募ステータス・作品番号（例: 101）の確認<br>

<br>・選考結果および審査員からの「公開コメント」の閲覧 |
| **保護者** | 応募者の保護者 | ・受領メール記載のワンタイムURLからの同意画面アクセス<br>

<br>・応募内容・個人情報利用規約の確認および同意手続き |
| **事務局スタッフ** | コンテスト運営事務局担当者 | ・全応募作品の一次審査（スクリーニングおよびルーブリック採点）<br>

<br>・作品番号による検索・管理<br>

<br>・一次選考通過作品（上位20名程度）のフラグ付け・指定<br>

<br>・全般的な応募データの閲覧・検閲 |
| **審査員** | 外部・内部のコンテスト審査員 | ・担当に割り当てられた二次選考作品（上位20作品等）の閲覧<br>

<br>・作品番号、ソート・フィルタリング機能を活用した担当作品管理<br>

<br>・リアルタイム順位およびスタッフ一次審査順位の確認<br>

<br>・二次審査用ルーブリック採点の入力（小数入力含む）<br>

<br>・公開コメント（応援メッセージ）および非公開コメント（内部メモ）の入力 |
| **システム管理者** | システム運用責任者 | ・スタッフ／審査員のアカウント発行・管理<br>

<br>・審査割り当て（重複設定）の構成<br>

<br>・最終集計結果・ランキングの出力・レポート化<br>

<br>・応募者への公開コメントフィードバックの一括公開設定 |

## 3. 機能要件

### 3.1 応募者・保護者向け機能（フロントエンド）

#### 1. 認証機能

* **Google ID連携認証 (Google OAuth)**: Googleアカウントを利用したワンタップログイン／新規登録をサポートする。
* **メールアドレス会員登録**: メールアドレスとパスワードによるアカウント作成。メールアドレスの実在確認を行う二段階認証を必須とする。

#### 2. 作品応募フォーム機能

応募者が作品を投稿するためのフォーム機能。入力項目および制約要件は以下の通り。

| 大分類 | 項目名 | 入力形式 | 必須/任意 | 制約・補足仕様 |
| --- | --- | --- | --- | --- |
| **自動発行** | **作品番号** | システム自動採番 | - | **【追加】応募受付順に「100」から始まる3桁の整数を自動発行（欠番可）。子ども自身が作品を特定・識別しやすくするためのID。** |
| **応募者情報** | 氏名 | 1行テキスト | **必須** | 全角文字（苗字・名前） |
|  | フリガナ | 1行テキスト | **必須** | 全角カタカナ |
|  | 学校名・学年 | ドロップダウン選択 | **必須** | 小学1年〜中学3年 |
|  | 保護者氏名 | 1行テキスト | **必須** | 未成年応募に伴う確認事項 |
|  | 保護者メールアドレス | メールテキスト | **必須** | 保護者同意メール送付用のアドレス |
|  | 保護者連絡先TEL | 1行テキスト | **必須** | ハイフンあり/なし両対応 |
|  | 応募形態 | ラジオボタン | **必須** | 「個人」または「チーム」 |
|  | チーム名・メンバー名 | 複数行テキスト | 任意 | 応募形態が「チーム」の場合のみ入力 |
| **作品提出** | 作品タイトル | 1行テキスト | **必須** | 最大 30文字 |
|  | **作品URL** | URLテキスト | **必須** | Scratch共有URL、MakeCode共有URL、GitHub Pages等の公開URL |
|  | **説明動画** | ラジオボタン ＋ 入力 | **必須** | 「YouTube URLの入力」または「MP4ファイル直接アップロード（最大100MB）」を選択 |
|  | **サムネイル画像** | ファイルアップロード | **必須** | PNG / JPG（最大 5MB、推奨アスペクト比 16:9） |
| **作品説明** | **短い説明** | 1行テキスト | **必須** | 最大 100文字（作品一覧画面等でのカード表示用サマリー） |
|  | **作品の詳細説明** | Markdownテキストエリア | **必須** | 最大 2,000文字。下記テンプレートテキストが初期値として自動セットされる |
| **確認・送信** | 個人情報利用同意チェック | チェックボックス | **必須** | 応募者本人の規約同意チェック |

* **「作品の詳細説明」用初期挿入テキスト（指定フォーマット）**:
新規応募時、テキストエリア内にあらかじめ以下の3つの見出しとガイド文が挿入表示される仕様とする。
> ## つくりかた
> 
> 
> （ここに作品のあそびかたや、つかいかたを書いてね）
> ## くふうしたところ
> 
> 
> （がんばったところや、じぶんだけのアイデアを書いてね）
> ## てつだってもらった ところ
> 
> 
> （おうちの人や先生に手伝ってもらったことがあれば書いてね。なければ「なし」でOK！）



#### 3. 保護者同意ワークフロー機能

1. **同意リクエストメールの自動送信**: 応募者がフォームから送信ボタンを押下した際、入力された「保護者メールアドレス」宛に作品番号が明記された専用の承認トークン付きURLを自動送信する。この時点での応募ステータスは「保護者同意待ち（仮応募）」とする。
2. **保護者専用同意画面**: 送信されたURLをクリックすると、専用のウェブ画面が開く。保護者は応募内容（作品番号・作品情報・個人情報）を確認し、「コンテスト応募および個人情報の取り扱いに同意する」ボタンを押下する。
3. **応募完了処理**: 保護者の同意アクションが完了した時点で、正式にステータスが「応募完了（審査対象）」へ遷移し、応募者および保護者宛に完了通知メール（作品番号を添付）が届く。保護者同意が得られていない作品は選考対象から除外される。

#### 4. マイページおよび作品修正・再審査連動機能

* **マイページ**: ログイン後、自身が応募した作品の一覧（**作品番号「#100」等の形式で強調表示**）および現在のステータス（「保護者同意待ち」「受付完了」「一次審査中」「要再審査」等）を閲覧可能。
* **差し替え・編集機能**: 応募締め切り日時までに限り、提出済みのすべての情報（タイトル、作品URL、動画、サムネイル、説明文章）の編集・更新を許可する。
* **再審査フラグのトリガー機能**: 既に審査員・スタッフによって採点（「審査済み」）された作品が応募者によって修正された場合、システムは作品データ更新を検知し、該当採点データのステータスを自動的に「要再審査」へと変更する。

### 3.2 審査・管理向け機能（バックエンド）

```
 [ 全応募作品 ] (保護者同意完了済みの作品のみ対象／作品番号100〜順次受給)
        │
        ▼
 【 一次審査 】 (事務局スタッフ：1作品につき 4〜5名で重複採点)
   ・ルーブリック5軸（独創性・技能・努力・目標:各1〜5点、その他:1.0〜5.0点、計25点満点）
   ・平均スコアを自動算出 ➔ 上位20名程度を「二次審査対象」として抽出
        │
        ▼
 【 二次審査・最終選考 】 (審査員：1作品につき 4〜5名で重複採点)
   ・ルーブリック5軸（独創性・技能・努力・目標:各1〜5点、その他:1.0〜5.0点、計25点満点）
   ・「作品番号」「採点ステータス」「採点結果スコア」による柔軟な検索・ソート機能
   ・スタッフ一次審査順位 ＆ 審査員総合リアルタイム順位の常時表示
   ・応募者によるデータ修正時、「要再審査」ステータスへの自動変更・アラート表示
   ・「公開コメント（応援メッセージ）」および「非公開コメント（評価メモ）」を入力
        │
        ▼
 【 結果確定・フィードバック開示 】
   ・最終ランキング自動生成
   ・公開コメントの内容確認後、応募者マイページへフィードバック開示

```

#### 1. 一次審査機能（事務局スタッフ向け）

* **一覧・スクリーニングUI**:
* 保護者同意が完了した全作品をリスト表示（作品番号順でのソートや作品番号によるダイレクト検索が可能）。不適切コンテンツや動作不全・リンク切れ作品の検閲・フラグ付けが可能。


* **一次採点画面**:
* 応募者の提出情報（作品番号、動画プレビュー、作品URLリンク、整形されたMarkdownテキスト）を1画面で確認可能。
* 1作品に対し 4〜5名 のスタッフが割り当てられ、独立してルーブリック評価を実施。


* **上位抽出機能**:
* 一次採点結果の平均点を算出し、スコア順で自動ソート。
* 上位20名程度の作品を一括指定し、「二次審査へ進出」ステータスへ更新する。



#### 2. 二次審査機能（審査員向け）

* **二次審査ダッシュボード（ソート・フィルタリング仕様）**:
* 担当作品一覧において、以下の基準による並び替え（ソート）および絞り込み（フィルタ）を提供する。
* **作品番号順ソート / 検索**: 作品番号（例: 100, 101...）によるダイレクト検索および昇順・降順ソート
* **採点ステータス順ソート**: 「未審査」➔「要再審査」➔「一時保存」➔「採点完了」
* **採点結果スコア順ソート**: 自身が入力した合計点（高スコア順／低スコア順）
* **リアルタイム順位順ソート**: 現在の審査員総合順位（1位〜20位）




* **リアルタイム順位表示機能**:
* 作品詳細および一覧画面において、以下の2つの順位情報をリアルタイムで表示する。
1. **一次審査順位**: 事務局スタッフによる一次審査結果の総合順位
2. **審査員総合順位**: 各審査員が入力した現時点の採点データをリアルタイム集計した総合順位




* **要再審査（修正検知）通知機能**:
* 採点完了後に応募者によって作品データが修正された場合、該当作品のステータスバッジが赤色の「要再審査」に変化し、修正された項目（例: 「作品URLが更新されました」）の差分ハイライトを表示する。審査員は内容を確認の上、再採点を行う。


* **詳細審査・採点画面**:
* **作品情報閲覧ゾーン**: 作品番号をヘッダーに大きく表示。MP4動画/YouTubeの埋め込み再生、Scratch等外部サイトへのリンク、整形されたMarkdownテキストを見やすく表示。
* **ルーブリック採点ゾーン**: 後述の5項目を入力。
* **コメント入力ゾーン**:
* **公開コメント（必須）**: 応募者向けの「応援コメント」。
* **非公開コメント（任意）**: 内部用の評価メモ。


* **機能**: 一時保存機能、および最終確定送信機能。



#### 3. 管理者機能（集計およびフィードバック管理）

* **自動集計エンジン**:
* 各作品に対して複数名（4〜5名）の評価点を集計し、平均値・標準化スコア・合計値を算出。「その他」項目の小数点入力により同点を防ぎつつ、厳密な順位を算出する。


* **コメント検閲および一括開示設定**:
* 審査員が入力した「公開コメント」一覧を管理者が事前確認。結果発表後、ワンクリックで応募者マイページへ開示する。

## 4. 採点基準（ルーブリック評価仕様）

一次審査（事務局スタッフ）および二次審査（審査員）における評価は、以下の5軸評価（合計25点満点）に基づく。

| 評価項目 | 定義・評価観点 | 入力形式 / 評価スコア | 補足仕様 |
| --- | --- | --- | --- |
| **1. 独創性** | 作品に、他の人とは違うオリジナリティやアイデアが加えられているか | 整数（1〜5点） | 1: 低い ～ 3: 標準 ～ 5: 極めて高い |
| **2. 技能** | 学年や年齢にふさわしい、プログラミングの知識・応用力・表現力が発揮されているか | 整数（1〜5点） | 1: 低い ～ 3: 標準 ～ 5: 極めて高い |
| **3. 努力** | 作品、応募フォーム、写真、動画などが、手間や時間をかけて丁寧に作られているか | 整数（1〜5点） | 1: 低い ～ 3: 標準 ～ 5: 極めて高い |
| **4. 目標** | 何かを便利にしたり、良くしたり、他の人を思いやったりする姿勢や目的意識があるか | 整数（1〜5点） | 1: 低い ～ 3: 標準 ～ 5: 極めて高い |
| **5. その他** | 上記4軸に収まらない総合的な魅力、将来性、意欲、感銘度など | 小数第1位まで入力可<br>

<br>（1.0〜5.0点） | 【同点回避用】<br>

<br>例: 4.3点、3.7点など細かな加減点を可能とする |

## 5. データベース構造案（主要エンティティ）

```
[ Users ] ──1:N──> [ Submissions ] ──1:N──> [ Evaluations ]
                      │                      │
                      ├──1:1──> [ Consent ]   └──1:N──> [ Comments ]

```

### 5.1 主要テーブル定義

1. **Users（ユーザーテーブル）**
* `user_id` (PK): ユーザー識別ID
* `auth_provider`: 認証プロバイダ (google / email)
* `email`: 応募者メールアドレス
* `name`: 氏名
* `name_kana`: フリガナ
* `school_name`: 学校名
* `grade`: 学年 (p1〜p6, m1〜m3)
* `guardian_name`: 保護者氏名
* `guardian_email`: 保護者メールアドレス
* `guardian_phone`: 保護者電話番号
* `role`: アカウント権限 (applicant / staff / judge / admin)


2. **Parent_Consents（保護者同意テーブル）**
* `consent_id` (PK): 同意管理ID
* `submission_id` (FK): 対象作品ID
* `token`: ワンタイム承認用トークン文字列
* `status`: 同意ステータス (pending / approved / expired)
* `approved_at`: 同意日時


3. **Submissions（応募作品テーブル）**
* `submission_id` (PK): 作品識別内部ID (UUID / AutoIncrement)
* `work_number`: **作品番号 (INT, 100から順次インクリメント採番。欠番可。応募識別表示用番号)【追加】**
* `user_id` (FK): 応募者ID
* `entry_type`: 応募形態 (individual / team)
* `team_name`: チーム名
* `team_members`: メンバー氏名
* `title`: 作品タイトル
* `short_description`: 短い説明 (100文字以内)
* `detailed_description`: 詳細説明 (Markdownテキスト)
* `work_url`: 作品共有URL
* `video_type`: 動画種別 (youtube_url / mp4_file)
* `video_location`: 動画URLまたはストレージパス
* `thumbnail_url`: サムネイル画像パス
* `status`: 選考ステータス (pending_consent / submitted / primary_passed / final_completed)
* `primary_rank`: 一次審査リアルタイム順位
* `final_rank`: 二次審査リアルタイム順位
* `created_at`: 応募日時
* `updated_at`: 最終修正日時


4. **Evaluations（評価・採点テーブル）**
* `evaluation_id` (PK): 採点識別ID
* `submission_id` (FK): 対象作品ID
* `evaluator_id` (FK): 採点者ID (Users.user_id)
* `phase`: 審査区分 (primary / secondary)
* `score_originality`: 独創性スコア (1〜5)
* `score_skill`: 技能スコア (1〜5)
* `score_effort`: 努力スコア (1〜5)
* `score_purpose`: 目標スコア (1〜5)
* `score_other`: その他スコア (1.0〜5.0、DECIMAL(2,1))
* `total_score`: 合計点 (最大25.0点、DECIMAL(3,1))
* `status`: 採点ステータス (unexamined / draft / completed / re_examine_required)
* `updated_at`: 採点日時


5. **Comments（コメントテーブル）**
* `comment_id` (PK): コメント識別ID
* `submission_id` (FK): 対象作品ID
* `judge_id` (FK): 審査員ID
* `public_comment`: 応募者向け公開コメント（応援メッセージ）
* `private_comment`: 運営内部用非公開コメント
* `is_published`: フィードバック公開フラグ (Boolean)
