# アプリA - アプリB 連携仕様書（APIキー認証方式）

## 1. 概要

本ドキュメントは、アプリA（Express）のデータベース（DB）に存在するデータを、アプリB（Next.js）のユーザーが画面上で選択し、手動でアプリBのDBに取り込む（同期する）ための実装仕様を定義します。

### 基本方針

* **直接参照の禁止:** アプリBからアプリAのDBへ直接接続せず、アプリAが提供するWeb APIを介してデータを取り込みます。
* **安全性の確保:** 共通の暗号化キー（`API_SECRET_KEY`）を用いた**APIキー認証**を行い、通信はすべてNext.jsのサーバーサイド（Server Actions）を経由させてキーの露出を防ぎます。

```text
    │<── 5. モーダル表示 ──│                                   │                          │
    │ (要/不要にチェック)  │                                   │                          │
    │                      │                                   │                          │
    │── 6. 「取り込み」 ──>│                                   │                          │
    │                      │── 7. POST /api/v1/items/fetch ───>│ (APIキーをチェック)      │
    │                      │    (選択したIDリスト送信)         │── 8. 詳細データ取得 ────>│
    │                      │<── 9. 詳細データ (JSON) ──────────│<── レコード返却 ─────────│
    │                      │                                   │                          │
```

## 3. 共通設定（環境変数）

アプリAおよびアプリBの環境変数ファイル（`.env`）に同一の認証キーを設定します。

```env
# アプリA・アプリB 共通
API_SECRET_KEY="your-random-secret-key-12345"

# アプリB（Next.js）側のみ
APP_A_URL="http://localhost:4000"  # アプリAのベースURL

```

## 4. アプリA（Express）実装仕様

### 4.1 認証ミドルウェア (`middlewares/auth.js`)

リクエストヘッダー `x-api-key` を検証します。

```javascript
function verifyApiKey(req, res, next) {
  const apiKey = req.headers['x-api-key'];
  
  if (!apiKey || apiKey !== process.env.API_SECRET_KEY) {
    return res.status(403).json({ message: '認証に失敗しました' });
  }
  next();
}

module.exports = verifyApiKey;

```

### 4.2 APIエンドポイント仕様 (`routes/sync.js`)

#### ① 連携データ一覧取得 API

手動選択モーダルに表示するためのデータ一覧を取得します。

* **HTTP Method:** `GET`
* **Endpoint:** `/api/v1/items`
* **Header:** `x-api-key: <API_SECRET_KEY>`
* **Response Body (200 OK):**
```json
{
  "success": true,
  "items": [
    { "id": "101", "title": "データ項目A", "updated_at": "2026-08-16T10:00:00Z" },
    { "id": "102", "title": "データ項目B", "updated_at": "2026-08-16T11:00:00Z" }
  ]
}

```



#### ② 選択データ詳細一括取得 API

ユーザーが選択したIDのフルデータを取得します。

* **HTTP Method:** `POST`
* **Endpoint:** `/api/v1/items/fetch`
* **Header:** `x-api-key: <API_SECRET_KEY>`, `Content-Type: application/json`
* **Request Body:**
```json
{
  "ids": ["101", "102"]
}

```


* **Response Body (200 OK):**
```json
{
  "success": true,
  "data": [
    { "id": "101", "title": "データ項目A", "content": "詳細テキスト...", "updated_at": "2026-08-16T10:00:00Z" }
  ]
}

```

## 5. アプリB（Next.js）実装仕様

### 5.1 サーバーアクション (`app/actions/sync.ts`)

ブラウザからAPIキーが見えないよう、Next.jsのサーバー側からアプリAへアクセスします。

```typescript
'use server';

const APP_A_URL = process.env.APP_A_URL || 'http://localhost:4000';
const API_SECRET_KEY = process.env.API_SECRET_KEY || '';

// アプリAからデータ一覧を取得
export async function getAppAItems() {
  const res = await fetch(`${APP_A_URL}/api/v1/items`, {
    headers: { 'x-api-key': API_SECRET_KEY },
    cache: 'no-store'
  });

  if (!res.ok) throw new Error('一覧の取得に失敗しました');
  return res.json();
}
```

## 6. セキュリティと運用上の注意点

1. **APIキーの隠蔽:** `API_SECRET_KEY` は必ずサーバー側の環境変数で管理し、`NEXT_PUBLIC_` などの接頭辞をつけてブラウザ側に露出させないでください。
2. **データの重複防止 (UPSERT):** アプリBのDBに取り込む際、`app_a_id` などの一意なキーを用いて「データが存在すれば更新、なければ挿入（UPSERT）」のロジックを実装してください。
3. **将来の拡張性 (SSO連携):** SSO導入時は、アプリA側の認証ミドルウェア（`verifyApiKey`）を「JWT/OAuth 2.0トークン検証」に置き換えることで、APIの口（エンドポイント）を変更せずにスムーズに移行可能です。
